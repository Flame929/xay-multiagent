## 待做

### 将来：参考 Magpie，直接接入 Agent App 的额度，而不只走命令行
- **是什么**：现在 xay 只通过各家官方命令行（codex / dsh / agy）派活。热门项目 [Magpie](https://github.com/yetone/magpie)（MIT）能把 WorkBuddy 这类 App 里的额度也借出来给别的 AI 用，不必非得有命令行。用户 2026-11-02 决定：**将来可能参考它的思路，直接接入 Agent App**。
- **为什么现在不做**：目前只走官方命令行，**完全是为了合法**。Magpie 的做法是拿账号凭据直接调厂商云端接口、冒充官方客户端、绕过厂商的拦截，违反本仓库「不读取 / 不保存 token 和 cookie，不做设备指纹伪装」的硬约束，还有被厂商封号的风险，不能照搬。
- **要做的话怎么做才合规**：先用官方出的命令行 / 协议接入（例如腾讯 CodeBuddy 的 `codebuddy` 命令行，有无头模式和 ACP），登录由官方工具自己管，xay 不碰令牌。接之前要先真机试：用 WorkBuddy 账号登录后扣的是不是 WorkBuddy 积分、输出里有没有用量和报错、能用哪些模型。额度可能只能手动填。
- **做之前**：先问用户；允许使用的模型要先写进 `AGENTS.md` 硬性约束。调研记录（来龙去脉、条款原文、风险）在 2026-11-02 的会话笔记里，需要时重新查。

### B 方案：部门负责人做成独立的 Claude 桌面对话
- **是什么**：现在部门负责人是总经理的子代理（A 方案，藏在总经理对话里）。B 方案是每个部门负责人开成一个独立的 Claude 桌面对话：用户能在侧栏看到"前端部负责人"之类的对话、点进去看它怎么监工、直接跟它说话；总经理和部门负责人之间用桌面版自带的跨对话消息互传（桌面 App 当"邮局"，对方忙就排队，回信同样寄回）。
- **为什么没默认用**：只有总经理是 Claude 桌面版时才有这个能力，Codex / dsh / agy 当负责人时用不了；每个部门多一个完整的 Claude 对话，更费额度。
- **用户决定**：默认 A；B 由 Claude 先测试，结果记在下面。
- **测试记录**（2026-10-30，Claude 开了一个 Sonnet 的独立对话「测试部负责人」）：
  - 通了：它读完 `prompts/dept-head.md`，从收件箱拿到前端部的需求单，一次拍板（modify：接下测试，但"今天能否上线"等测完再说），再用桌面版跨对话消息把汇报寄回总经理，全程无人干预。
  - 它指出的问题：结论署名成了总经理（已修：署名为收到需求单的部门）；收件箱里通知和需求单混在一起（已修：每条前面标类型）；需求单标题太短（已放宽到 40 字）；"能否上线"这类要结论的需求没有规范写法（待做：需求单加"要什么结论"字段）。
  - 局限：独立对话是一次性的，要持续监工得一直挂着 `xay inbox --wait`，或由总经理按需唤起；开一个就多一个完整的 Claude 对话。
  - 结论：能用，适合用户想亲自盯某个部门时开；日常仍默认 A 方案。
