# 看板 v5 需求（用户原话整理，负责人定稿，优先级高于 ui-v4 的相关部分）

## 用户的不满
- 左侧几十个"未命名会话"。用户只开了几个负责人对话，看板上就应该只有几个。
- 每个会话点进去只看到一个节点，看不出这个对话调用了哪些 AI、每个 AI 被吩咐了什么、做了什么。
- 不是流式的，体验像在看静态报表。
- 要求：**高度参考 Claude 桌面版（Code 标签页）的前端结构**，见 `research/claude-desktop-ui.md`。

## 必须达到的结构
1. **左侧栏 = 负责人对话列表**：一个负责人对话（例如一个 Claude Code 对话）对应一行，按工作区分组，和 Claude 桌面版的侧栏一样。
   - 标题优先用 Claude 桌面版里这个对话的真实标题（见"数据"第 3 条），其次用 `xay session begin --title`，再次用该对话第一次派活的任务名。
   - 每行显示状态点：进行中、等你决定、完成。
   - 没有记录负责人对话的旧数据，每个工作区只合并成一行"以前的任务"，默认折叠。
2. **对话主视图 = 按 AI 分区的聊天记录**：
   - 顶部是对话标题和一句话现状。
   - 下面每个被调用过的 AI（Codex、dsh、agy）各占一个区域。宽屏时并排成列，窄屏时用标签页切换。
   - 每个区域里按时间顺序排列，像聊天记录：
     - **负责人消息**：负责人下达的任务，以及插话、改指示。默认显示大白话标题加前 3 行，可以展开看全文。
     - **AI 消息**：
       - 执行过程：工具调用一行化（读了某某文件、运行了测试 · 失败），思考默认折叠，和 Claude 桌面版一样。
       - 正在进行的那条消息要**流式**显示：文字逐字出现，新的工具调用实时追加。
       - 最终回复完整显示，不折叠。
       - 改动的文件显示为可点开的文件卡。
   - 同一个 AI 同时跑多个任务（例如 Codex×3 并行）时，在该 AI 的区域里分成多条并行的子线程，用"#1 #2 #3"标识，每条子线程可以折叠。
   - 每条正在进行的 AI 消息下方有控制条：暂停/继续、停下、说一句。按能力显示，规则沿用 ui-v4。
   - 依赖关系图降级为顶部的一个可选视图，默认不显示。
3. **"我的事"首页**保留，但改成和左侧栏一致：一个负责人对话一行。

## 数据
1. **自动识别负责人对话**：
   - xay-run 和 xay-dag 在没有收到 `--session` 时，按以下顺序自动识别：
     - `XAY_SESSION`
     - `CLAUDE_CODE_SESSION_ID`（同时记录 `CLAUDE_CODE_HOST_SESSION_ID`）
     - Codex、dsh、agy 当负责人时各自的会话环境变量（查一下它们分别是什么，查不到就留空）
   - 识别到之后，自动登记到会话表里，不要求负责人先执行 `xay session begin`。
2. **流式数据**：
   - xay_agent 把增量文字（delta）写进一个有上限的实时流文件（例如 `stream.jsonl`，只保留当前轮，轮次结束后清空或截断），或者通过别的低开销方式提供给看板。
   - 看板服务用 SSE 推送增量事件和文字片段，页面不再整页轮询。
   - 断线后能续传。
3. **对话标题**：在 `~/Library/Application Support/Claude/` 下找到 Claude 桌面版保存会话标题的位置。用 `CLAUDE_CODE_HOST_SESSION_ID`（`local_…`）或 `CLAUDE_CODE_SESSION_ID` 做匹配，只读、只取标题。找不到就退回上面的兜底规则，并在汇报里说明找到了什么。
4. **接口**：
   - `/api/state` 的侧栏数据改为"工作区 → 负责人对话"。
   - 新增 `/api/conversation?id=`，返回该对话下每个 AI 的消息列表：负责人消息、AI 消息，以及各自的状态、动作、回复和文件。
   - 新增 SSE 事件 `message.delta`、`message.append`、`message.update`。
   - 接口文档写进 `references/plans/ui-v5-api.md`，前端严格按这份文档实现。
