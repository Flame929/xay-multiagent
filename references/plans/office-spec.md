# xay 公司页 / 任务画布 / 负责人流程 说明书（定稿，2026-10-31）

> 这是唯一的依据。页面、命令、文档都照这份改；改规则先改这份，再改代码和测试。
> 每条规则后面的【测】是要写成自动测试的检查点。

## 一、四层结构（不再改）
| 层 | 谁定 | 是什么 | 账本 |
|---|---|---|---|
| 大任务 | 负责人（主 AI，页面上叫"负责人"） | 这个对话要完成的整件事 | conv |
| 中任务 | 负责人决定怎么分：按前端 / 后端，或按功能；名字由负责人起 | 一个组，**每个中任务一个监工**；中任务之间有先后（第几步），同一步里的可以同时做 | part |
| 小任务 | 负责人交给某个 AI | 一个 AI 的一件活 | task |
| 步骤 | **AI 自己拆** | AI 开工前读员工手册和任务卡，用【计划】写出步骤；程序显示，AI 专心干活 | task.planned |

- 中任务里不再分部门。页面上一律叫"大任务 / 中任务 / 小任务 / 步骤"。【测：页面和命令输出里不出现"AI 的活""部门"当层级名】

## 二、公司页怎么摆
1. **从上往下一步一步排**（2026-10-31 用户选定，取代原来的"同一步全部横着并排"）：左边一条细细的**步骤时间线**（✓ 做完、● 正在做、○ 还没开工），右边每一步一块。【测】
2. **做完的步收成一行**：这一步所有中任务都做完 → 一行"✓ 第 1 步 · 4 组都做完"+ 每组一个小芯片（编号 + 名字）+ ▸，点开再展开房间。**还没开工的步**也是一行："○ 第 4 步 · 还没开工 · 等第 3 步"+ 芯片。【测】
3. **正在做的步展开**：房间按固定宽度（随人数）排成网格，一行最多两个（屏幕够宽时三个），放不下就换到下一行，**不再横向拉得很宽**；这一步里已经做完的组用小芯片放在这一步最上方，不占房间位置。打开页面默认 **100% 大小**、停在正在做的那一步，字始终看得清；仍然能拖动和缩放。【测：正在做的步里房间不超过 3 列、默认缩放 100%】
4. **房间大小按人数来**：房间宽度 = 监工席 + 人数 × 工位宽，不留大片空白；一个人的房间就是"监工 + 一个工位"那么宽。【测：1 人房间宽度 < 2 人房间宽度，且没有占位空框】
5. **监工席**：监工头像 + "监工" + 验收方式小标签；验收方式是"负责人亲自审"时，监工席正下方再叠一个负责人格子（见第 10 条）。【测】
6. **谁坐哪**（规则写成一个函数，有测试）：
   - 员工坐在他**正在做 → 排队 → 最近做完**的那件小任务所在的中任务房间。
   - **做完了就留在原房间睡觉**（休眠表情），不离开、不显示"人去别处了"。
   - 只有当这个 AI **又被派到别的中任务**里干活时，他才搬过去（同一个人同时只坐一个房间）。
   - 一个中任务里**所有人都搬走了**（房间里一个人都不剩）：房间**收起成一行简单记录**（编号 + 名字 + "做完 15/15 件" + 验收方式），**监工也一起下班**（不显示监工席）。点这行能展开看它的小任务清单。【测】
7. **不抖**：数据刷新时只更新变了的地方（文字、状态、头像表情），房间和工位**不整块重建**，页面高度和滚动位置不变；新增 / 搬走的人用过渡动画。【测：连续两次相同快照渲染后 DOM 节点是同一批；滚动位置不变】

8. **能拖动**：公司页和画布一样，按住空白处拖动平移、滚轮 / 触控板缩放，角上有"适应屏幕""100%"。【测】
9. **左上角切换**：页面左上角一组切换按钮"看板 / 公司页 / 任务画布"（看板给懂的人看，公司页和画布给不懂的人看，是两套对应的体系），右上角不再放画布按钮。
10. **负责人**：主 AI 一律叫"**负责人**"（不再叫"总经理"，因为已经不按部门分）。验收方式是"负责人亲自审"的中任务：在监工席**正下方**再放一个和监工席**一模一样的格子**（头像换成负责人的，名字"负责人"，小标签"亲自审这一组"），两个格子上下叠成一列；**没有电脑桌**，不占工位那一排。【测：负责人格子和监工格子同宽、左边对齐、在监工下面；里面没有电脑桌】
11. **留白**：页面左右各留出边距，房间不贴边。

## 二½、"需要你"弹条
1. **说人话**：每条写清"发生了什么、为什么要你、你选了会怎样"，不出现"改动先保留""桌子"这类内部说法。例："Gemini 7 做『在 Windows / Linux 上也不报错』时网络断了，改好的 5 个文件还没放进项目。你可以：放进项目 / 让他接着做 / 不要了。"
2. **附文件**：凡是和文件有关的（改动、审查、冲突），列出相关文件，**点一下在页面里打开**（看全文或看改了哪几行），不用自己去找。【测】
3. **交出去**：每条都有"交给监工"和"交给负责人"两个按钮：
   - 交给监工 → 监工按默认做法处理（改动没问题就放进项目、网络断了就接着做、没动静就再等等、审查就让审查 AI 看……每种情况的默认做法写在代码里一张表上）；
   - 交给负责人 → 这条从你的弹条里消失，负责人（主 AI）在 `xay2 wait` 里处理；
   - 点弹条右上角的"关掉"= 交给负责人。【测】

## 二¾、看板（给懂的人看，2026-11-02 用户要求）
1. **左上角对齐**：看板（对话版 `/`、纯 CLI 版 `/board`）左上角放同一组"看板 / 公司页 / 任务画布"切换，**位置、大小、样式和公司页一模一样**，来回切换时这组按钮不跳；当前页那个按钮高亮。看板侧栏原来的"我的事"、搜索框排在切换下面。没选对话时，"公司页"去 `/org`，"任务画布"去 `/org?canvas=1`；选了对话就带上这个对话。【测：三个页面上切换条左上角坐标、宽、高都相同】
2. **右上角工具**：全部 / 失败筛选、单列 / 并排、阶段概览、**纯 CLI**、**修改文件**。**去掉"公司"按钮**（左上角已经能切），侧栏和顶部也不再放"公司页 →"。【测：看板上找不到"公司"按钮，有"纯 CLI""修改文件"】
3. **纯 CLI**：切到同一个对话的 `/board?conv=<对话>`（每名员工一列，只看他的命令行）；在纯 CLI 页上这个按钮是按下状态，再点一下回到对话版的同一个对话。两边按钮在同一个位置。【测】
4. **修改文件**：打开后列出这个对话里**所有被改过的文件**（按文件归并，同一个文件只出现一次），每行写：文件路径、谁改的（哪件小任务、哪个员工、第几轮）、状态（已放进项目 / 还在员工桌上 / 等你决定）。**点一个文件，在右侧面板里看 diff**（绿色加的行、红色删的行、蓝色段落头）；同一个文件被几件小任务改过，就按时间先后一段一段列出来，每段头上写"谁 · 哪件小任务 · 什么时候"。没有改动时写"这个对话还没改过文件"。【测：示例数据里列出文件、点开有 diff】
5. **diff 要准**：每件小任务的 diff 只算**这件小任务自己**的改动（员工桌上"这件小任务落地"那个标记和它前一版之间），不能拿员工最近一件活的改动顶替；还没落地的小任务显示桌上现在的改动。拿不到时写"拿不到这件小任务的改动"，不报错。【测：同一个员工先后做两件小任务、改不同文件，两件各自的 diff 只含自己的文件】
6. **直播只开一条连接**（2026-11-02 用户要求修）：纯 CLI 页每名员工一列、公司页每个工位的小屏、放大的终端窗口，所有员工的命令行**在同一个页面里共用一条直播连接**（`/api/v2/live?ems=员工1,员工2,…`），不按人数开。员工再多、页面停多久，都不会占满浏览器的连接、让同一个浏览器里别的看板页打不开或卡住。要看的员工变了（多了一列 / 少了一列）就换一条新连接，旧的先断开；已经显示过的行不重复显示，换连接时不从头重发。页面藏到后台 10 秒后断开，回来再连。【测：10 名员工的纯 CLI 页同时只有一条 /api/v2/live 连接；服务端一条连接按员工分别送出各自的行；带上"已经看到哪一行"重连时不重发】

## 三、任务画布
- 最左"大任务" → 每一步一列中任务（同一步并行的上下排在同一列，不同步之间用竖向虚线隔开并标"第 n 步"）→ 每个中任务右边是它的小任务（有先后的连成线，并行的分几条线）→ 点小任务看步骤和详情。
- 和公司页同一套编号、颜色、状态、验收说法（plan-model.js 是唯一来源）。【测：已有】
- **Esc**：有高亮时按 Esc 先取消高亮；没有高亮时再按 Esc 才关掉画布。【测】
- **不抖**：数据刷新时画布不整块重画，节点按编号复用、只改变了的文字和状态；拖动位置和缩放比例不变；只有中任务 / 小任务增减时才重新排版，而且平滑过渡。【测：连续两次相同数据刷新后节点是同一批、视图位置不变】

## 四、负责人流程（固化成工具，换哪个 AI 当负责人都一样）
1. `xay2 begin --title "大任务（大白话）"`。
2. `xay2 plan template > plan.json`：生成一份带中文注释的计划模板（大任务 → 中任务 → 小任务，每格写什么、举例）。
3. 负责人把模板填好（**全部用大白话**：中任务写清"做完能得到什么"，小任务标题不许像代码；技术细节写在任务卡里）。
4. `xay2 plan apply --dry-run plan.json` 检查 → 有问题逐条改 → `xay2 plan apply plan.json` 一次建好。**不经过 plan apply / plan part 建的小任务（直接 plan add 且没有 --part）会被提示"先放进一个中任务"**。
5. 之后的事都由程序做：派人、员工先拆步骤、监工验收（不合格打回一次）、大白话汇报、页面自动画出来。负责人只处理"需要你"、验收、改计划。
6. SKILL.md 第 2~3 节就写这 5 步，不再写别的花样。

## 五、改东西的规矩（给负责人自己）
- 先改这份说明书 → 再写 / 改测试 → 再改代码 → 截图对照说明书核对 → 再交给用户看。
- 同一时间页面只让一个人改；后端可以并行，但不碰同一批文件。
