# 第八版：公司页做成"动画片"（负责人定稿，各执行者唯一依据）

接在第七版（`ui-v7-characters.md`，AI 娘头像角色）之后，只改公司页 `scripts/xay-org.html` 和看板主页的额度面板。

## 用户原话要点（2026-10-30）
- 名字正常点：员工就叫"AI 名字 + 序号"（Codex 1、DeepSeek 2、Gemini 1）。
- 部门分区要分开一点；现在的连线太密，看不出谁给谁干活。
- 每个部门的监工要看得见。
- 边上有个东西一直左右晃（待答复需求连线上来回跑的小圆点）——去掉。
- 写信传递要更可视化，并且像聊天记录一样**按时间顺序规整地排在右侧**。
- 整体像动画片，用动画展示具体进程。
- 额度面板（看板主页左下角）美化。

## 1. 名字
- 人员目录 `buildRoster` / `whoIs`：每个员工按 AI 类型发号，`AI_NAMES = { codex: Codex, dsh: DeepSeek, agy: Gemini, gm: Claude }`，
  第一次出现时发号，之后不变。原来的具名（如"角色框架"）放在悬停提示里。
- 总经理显示"总经理"；部门显示部门名；部门监工显示"<部门名>监工"。

## 2. 布局：办公楼
- 顶部：总经理办公室（Claude 娘，大一号）。
- 下面：每个部门是一间**独立的房间**（卡通风：墙、地板、门牌），房间之间留足间距（宽屏两列，手机一列）。
- 房间左边是**监工席**：`head=claude` 显示小一号 Claude 娘 + "监工 · Claude"；`head=rules` 显示一个小机器人 + "规则监工"。
- 房间里是员工工位（第七版的角色坐在显示器后面）。
- **删掉跨部门消息弧线和来回跑的小圆点。** "谁给谁干活"用一条规整的组织树线表示：总经理 → 各部门房间（竖干线 + 横线 + 下垂线，静态，不晃）。

## 3. 写信动画（"动画片"的核心）
- 新消息送达（`delivered` 由假变真或新出现且已送达）时：一封信封从发信人的工位飞到收信人（员工工位 / 部门门牌 / 总经理），
  沿弧线飞 ~1.2 秒，落地时收信人头顶冒一下信封图标；收发双方切到 `talking` 2 秒（第七版已有）。
- 一次最多同时飞 3 封，其余排队；`prefers-reduced-motion` 时不飞，只在信件栏里高亮。

## 4. 右侧信件栏（按时间顺序，像聊天记录）
- 标签名"信件"。**从上到下按时间正序**（最早在上、最新在下），新信件出现时自动滚到底部并有滑入动画。
- 每封信一行气泡：左边发信人小头像（`XayOrg.avatarHtml`），头部写"Codex 1 → 前端部 · 需求 · 12:03"，
  下面主题（粗体）和正文（最多 3 行，可点开看全文）。
- 类型用大白话和颜色：request 需求（橙）、decision 结论（绿）、escalation 上报（红）、tell/reply 留言（蓝）、report 汇报（灰）、auto 系统（灰）。
- 答复（`reply_to` 指向某封信）缩进挂在原信下面，像对话回复；原信显示"待答复 / 已答复"。
- 送达状态：已送达 ✓ / 投递中（小沙漏）。不显示 `type=delivered` 的内部行。
- 点击信件：对应的发信人和收信人工位闪一下高亮。

## 5. 进程动画
- 工位下方一条状态条：working 时是流动的条纹进度条 + "第 N 轮"；done（working→idle）时打勾并撒彩带；failed 变红；waiting 显示排队沙漏。
- 角色本身的动作和特效沿用第七版。

## 6. 额度面板（看板主页 `scripts/xay-watch.html` 左下角）
- 每条线路一张小卡片：AI 色块、线路名、状态标签（充足 / 偏紧 / 用完 / 上限未知）、"近 5 小时用量"大数字（中文单位：万 / 亿）、每小时速度、
  剩余百分比进度条（有 `remaining_pct` 时）或相对用量条（没有时，按四条线路里最大的当满格）、重置时间、"最多用一半"等说明。可折叠。

## 7. 验收
- `python3 -m unittest discover -s tests` 全过；改过的页面抽出脚本 `node --check`。
- 浏览器看 `/org?demo=1`（示例模式会随机变状态、送信）和真实数据，宽屏和 390px、明暗两色。
