# 第九版（草案，已被第十版吸收）：协作协议 —— 让每个 AI 自己汇报，页面只负责画

> 2026-10-30：用户决定从底层重构为 V2，本草案的思路（事件账本、统一命令、页面只读快照）已并入 `arch-v10-rebuild.md`，以第十版为准。

## 为什么要做（2026-10-30 用户提问："是不是得做一整套协议或者工具？不然永远都是主 agent 一直在改？"）

做第七、八版公司页时暴露的根本问题：

1. **页面在"猜"状态**：信息散在派活总表、每次运行的目录、留言总线、部门文件、会话文件里，编号还对不上
   （看板按"对话"查，派活记在 xay 会话下），所以真实页面长期是空的，每加一个视图都要负责人改好几处代码。
2. **没人汇报"做到哪一步"**：系统只知道一件活开始了、结束了，中间的进度只能靠执行者最后的技术汇报，小白看不懂。
3. **任务拆解不是一个"东西"**：计划只存在负责人脑子里和任务卡里，部门之间辩论后想改计划，没有地方改、也没有记录。

## 方案：一份协议 + 一套命令 + 只读的页面

### 1. 单一事实来源：每个对话一本"事件账本"
`~/.xay/org/<对话>/events.jsonl`，只追加不修改。每行一个事件，固定字段 `{v, ts, by, type, ...}`：

| 事件 | 谁写 | 用途 |
| --- | --- | --- |
| `dept.created` / `dept.closed` | 总经理 | 组部门、关部门 |
| `task.created {id, title, owner, dept, deps}` | 总经理 / 部门负责人 | 任务拆解里的一件事（标题必须是大白话） |
| `task.assigned {id, owner}` | 总经理 / 部门负责人 | 交给谁（可改派） |
| `task.progress {id, step, of, text}` | 执行者 | "第 2 步 / 共 4 步：写测试"（大白话） |
| `task.done / task.failed {id, result}` | 执行者 / 系统 | 做完、没做成（一句话结果） |
| `msg.request / msg.decision / msg.escalation / msg.tell` | 任何人 | 部门之间的信件（现有留言总线并进来） |
| `plan.proposed {changes, reason, ref}` | 任何人 | 辩论后提议改计划（改派、拆分、删掉、加一件） |
| `plan.decided {proposal, verdict, by}` | 部门负责人 / 总经理 | 拍板；同意就生效，计划版本 +1 |

页面和命令行都只读一个东西：把账本从头"合起来"得到的当前快照（谁在哪个部门、每件事交给谁、做到第几步、计划第几版、改过什么）。

### 2. 一套命令：所有 AI 都用同一套 `xay` 命令写账本
- 总经理 / 负责人：`xay plan add "做商品图轮播" --to Codex1 --dept fe`、`xay plan move <任务> --to <人>`
- 执行者：`xay progress "第 2 步/共 4 步：写测试"`、`xay done "轮播做好了，手机上也能滑"`（任务卡自动附上"每做完一步汇报一次"）
- 辩论后改计划：`xay plan propose --reason "数据部人手不够" move 算运费 --to 页面部` → 对方负责人 `xay answer <id> accept` → 计划自动更新
- 现有的 `xay-run` / `xay-dag` 派活时自动写 `task.created`、`task.assigned`，结束时自动写 `task.done/failed`，不改用法。

### 3. 页面只负责画
`/api/org` = 账本快照；公司页、看板、手机端都只是不同的"画法"。以后要加视图（比如甘特图、日报），不用碰派活逻辑。
协议写成 `references/protocol.md`（字段表 + 例子）和一组"协议测试"：谁写都必须过这组测试。

## 要不要单独建一个新项目？—— 建议：先不拆仓库，在 xay 里分三层

- **不拆的理由**：派活、驱动各家 AI 的命令行、看板都已经在 xay 里而且能用；另起一个项目要把这些再搬一遍，两边维护，收益只是"看起来干净"。
- **怎么做**：在仓库里明确分三层——`scripts/xay_protocol.py`（账本读写 + 合并成快照，零依赖）、命令行（`xay plan / progress / done`）、页面（只读快照）。协议有版本号 `v`，以后真要拆出去做成独立工具或开源，直接把协议层搬走即可。
- **什么时候再拆**：如果以后要让别人的工具（不是 xay 派出来的 AI）也接进来，或者要单独发布，就把协议层单独成库。
