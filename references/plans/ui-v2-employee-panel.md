## 用户原话要点

- 第 2 版"还是很多说明性文字"：工作笔记是啥、记忆下面又是啥、"还很清醒 / 还没整理过"重复，"现在没在干活、上一件做完了"别扭。

## 参照：Claude Code 自己的子代理和任务清单

子代理卡片一眼能看懂的只有这几样：**任务名、一个状态词（在跑 / 做完了）、用时、最后一个动作、最终汇报**；token 数和工具次数是给程序员看的。任务清单只用 **☐ / ● / ✓ + 序号 + 一句话**表示"共几步、哪步在做、哪些做完"，从不解释。

提炼成本栏的规则：

1. **只摆数字和事实**。标签最多 4 个字，不写"为什么 / 之后会怎样"的句子。
2. **拿不到就写"—"**；这一家根本给不出来的写"这家看不到"。不编、不估。
3. **同一件事只说一次**（状态只在名片上说，结果只在"现在"块里说）。

## 看他的屏幕（终端窗口，`V2/web/lib/cli-view.js`）

- 普通脚本（不是模块），挂在 `window.XayCliView`；样式自己注入，不靠外部 CSS。**只读**，不发任何写请求。
- 内容 = 直播通道原样（`/api/v2/live?em=…&tail=N`，**不带** `plain`）：命令写成 `$ 命令` + 输出（灰）、他说的话（白）、思考（灰色斜体；Gemini 没有）、工位状态（`#` 开头，暗色）。连续的同类片段拼成一段。实时往下滚；往上翻时不抢滚动（右下角出"↓ 最新"）。不在干活时显示最新一段记忆的最后一段记录。标题栏右边：他在干活（工位卡片 `data-state=working`）或 90 秒内有新行时写"直播中"，否则写"最近一段 · 23:13"。
- 脱敏：直播文件在工位写入时已过 `redact`；页面显示前再遮一次常见密钥样子（`sk-…`、`Bearer …`、`ghp_…`、`KEY=…`）。
- 入口：① 详情栏"现在"块的"看他的屏幕" → `open`；② 偷看屏幕（`desk-fx.js`，另一个会话负责）：点工位电脑 → 小屏里 `mini` → 点小屏 → `open`。
- 接口（给偷看屏幕那边用）：
  - `XayCliView.open(emKey)` → `boolean`：打开放大窗口（z-index 1000，高于小屏的 90），带关闭按钮，Esc / 点窗口外面关闭；`emKey` 是 `'gm'`、空或格式不对时不打开、返回 `false`。再次调用换人。
  - `XayCliView.mini(emKey, containerEl)` → `{ stop() }`：往容器里画最近 10 行、10px 等宽、深色底、实时滚动；还没输出 / `'gm'` / 未知 key 时画一行"等待输出…"，不报错；`stop()` 断开连接、清空容器，可重复调用。
  - `XayCliView.close()`：关掉放大窗口。

- 展开的部门超过 6 件时，最前面做完了的收成一行"前面做完 N 件"，点开看全部。

### token 消耗 / 速度（额度 ｜ 记忆 下面）

| 显示 | 数据从哪来 | 精度 | 拿不到 |
| --- | --- | --- | --- |
| 圆环外圈 + "这件活 327万 / 500万 65%"："现在"块那件（重试几次加起来）用了多少，对着这件活的 token 预算 | 账本每一轮：`turn.ended.usage.total`、一轮中途的 `context.updated.turn_tokens`、直播文件的用量行，三者取大 | 收工的轮是准数；正在做的那一轮跟着直播用量行走（Codex 每次模型回复一条、dsh 每步一条、agy 每步一条） | 这件活一轮都没跑过：这一行不出现；有一轮没报数：数字前写"约" |
| 圆环内圈 + "今天 879万 / 5000万 18%"：他今天（本机 0 点起开工的轮）一共用了多少，对着每人每天的 token 预算 | 同上 | 同上 | 今天没干过活写 0（真是 0） |
| "速度 最近 1 分钟 9034 /秒"（大字） | 直播文件的用量行：这一轮最近 60 秒累计数涨了多少 ÷ 60（开工不到 60 秒从开工算起） | 粒度 = 一次模型回复 / 一步；跑长命令、没调模型时就是真的 0 | 不在干活不写；这一轮还没有用量行、或开工不到 5 秒不写 |
| 一排 30 个方格（像 GitHub 方格）："30 分钟前 … 现在"，一格一分钟，越深用得越多（按这 30 分钟里最多的那一格分 4 档），鼠标放上去看"01:23 · 12万" | 同上 | 每格 = 那一分钟里累计数涨了多少 | 最近 30 分钟没有用量行：不画 |

- 口径都是 in + out + cached（和 `turn.ended.usage.total`、预算的 token 线一致）。Codex 每次请求都会把整段上下文再算一遍，所以每秒几千到上万是正常的。
- 预算上限来自 `reactions.json`（默认每件活 500 万、每人每天 5000 万）；读不到就只写数、不画圆环。Gemini 不按 token 管预算（它报的 token 是每一步把整段对话重算一遍再相加，额度按每天调用次数管），所以 Gemini 只写数、不画圆环。只有一圈有数时画在外圈。
- 他在干活时详情栏每 15 秒重拉一次（速度只在接口里算，快照里没有）。
- 工位改动只有一小段：适配器每次报 usage（带这一轮累计 `turn_total`）时，`LiveWriter.usage(轮, 累计数)` 往直播文件写一行 `{kind: usage, turn, tokens}`；没变不写，同一轮隔不到 1 秒的攒着由 tick / flush 补写。不进账本；直播推送（终端窗口、在想 / 在做）和步骤按 kind 过滤，看不到这种行。旧工位写的直播文件里没有这种行，所以**新工位上线之前速度和方格都不出现**（消耗照常从账本算）。
