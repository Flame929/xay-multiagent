# xay 维护说明（开发与发布备忘）

本文档记录 xay 开发仓库的内部结构、部署同步流程与维护约定，供维护者与参与开发的 AI 查阅。第一次使用 xay 的用户请先阅读根目录的 [README.md](../README.md)。

---

## 1. 副本关系与部署机制

在维护者本地环境中，通常存在两个副本，请勿混淆：

| 位置 | 角色 | 说明 | 是否允许直接修改 |
| --- | --- | --- | --- |
| `<开发仓库根目录>`（即当前仓库） | **开发仓库** | 所有功能开发、重构和修复均在此完成 | **允许** |
| `~/.agents/skills/xay-multiagent-workflow/` | **安装/生效副本** | 各 AI 工具日常调用的执行路径 | **禁止直接修改** |

- 历史运行记录存放在 `~/.xay/` 目录下（看板会读取运行历史，请勿误删）。
- 当改动完成并通过测试后，维护者运行 `scripts/xay-deploy` 将代码同步到安装副本（部署脚本会自动预检测试，并拦截非法的直接手改）。

---

## 2. 仓库目录结构

| 目录/文件 | 作用说明 |
| --- | --- |
| `SKILL.md` | 给主 AI（总经理）阅读的工作流操作指南（核心文件，修改需极为慎重） |
| `V2/` | **第十版重构代码**（架构见 `references/plans/arch-v10-rebuild.md`）：包含账本协议、管家服务、长期工位及 `xay2` 命令行工具。公司页默认端口 7879，任务看板默认端口 7878 |
| `scripts/` | 入口分发脚本 `xay`（由 `xay_switch.py` 调度，默认转交 V2）及历史维护辅助工具 |
| `scripts/xay_drivers/` | 各 AI 命令行客户端驱动（Codex / dsh / agy 等） |
| `scripts/legacy/` | 第三版旧程序存档，仅作为紧急回退备份（`XAY_LEGACY=1`），**已冻结不改** |
| `prompts/` | 注入任务卡的执行准则模版及各部门负责人提示词 |
| `references/` | 架构参考、各 AI 角色画像、评测指标与接口规范（索引见 `references/ARCHITECTURE.md`） |
| `references/plans/` | 架构设计文档归档 |
| `references/backlog.md` | 待办需求与优化清单 |
| `assets/` | 辅助资源、通知小程序图标与源文件 |
| `tests/` | 自动化测试套件；其中 `tests/evidence/` 为真实验收留证，**只读** |

## 3. 常用维护与测试命令

```bash
# 运行 V2 核心测试（推荐，耗时约 1~2 分钟）
python3 -m unittest discover -s V2/tests -p 'test_*.py'

# 跑旧版系统测试
python3 -m unittest discover -s tests

# 本地以独立端口启动开发调试版管家（不占用默认 7878 / 7879 端口）
XAY2_HOME=/tmp/xay_dev XAY2_NO_SCHEDULER=1 V2/bin/xay2 office start --port 7882

# 验证通过后部署发布到生效副本（--restart-board 可重启后台服务）
scripts/xay-deploy
```
